[1] EXECUTIVE SUMMARY & CORE MISSION
--------------------------------------------------------------------------------
AI Travel Charming Chat is an enterprise-grade Chatbot-as-a-Service (CaaS) and
Retrieval-Augmented Generation (RAG) platform. It is engineered for travel
agencies, hotels, tourism operators, and e-commerce websites.

The platform allows business owners to:
1. Register and manage custom AI Bot personas via a Developer Dashboard.
2. Upload proprietary knowledge bases (PDF, TXT, DOCX, Markdown, FAQs) or
   crawl website URLs to automatically index domain-specific facts.
3. Generate scoped API keys (Public Widget Keys and Secret Server Keys).
4. Embed an intelligent, floating chatbot widget on any external website using
   a single HTML <script> tag:
     <script src="https://example.com/widget.js" data-bot-key="pk_live_..." defer></script>
5. Ground customer inquiries strictly in business facts via vector embeddings,
   eliminating LLM hallucinations while enforcing strict domain whitelisting
   and credit-based rate limiting.


[2] TECHNOLOGY STACK
--------------------------------------------------------------------------------
- Full-Stack Framework: Next.js 14 (App Router, Server Actions, Route Handlers)
- Language: TypeScript & Modern JavaScript (ES2022+)
- Database & ORM: SQLite (Local Dev) / PostgreSQL (Production), managed via Prisma ORM
- AI Inference Engine: Google Gemini API (gemini-3.5-flash-lite / gemini-3.8-flash)
- Vector Embeddings: Google Generative AI (gemini-embedding-001, 768 dimensions)
  with built-in deterministic mathematical fallback embedding for offline/testing.
- Client Embed Script: Pure Vanilla JavaScript (<16KB), zero external dependencies,
  isolated within a closed Shadow DOM.
- Styling: Tailwind CSS (Sage green theme, topographic aesthetic)
- Key Security Pattern: Slip2Go architecture (One-way SHA-256 key hashing)

[4] HIGH-LEVEL ARCHITECTURAL MODULES
--------------------------------------------------------------------------------

A. DEVELOPER DASHBOARD (/dashboard)
   - Bot Management: Create, edit, and configure chatbots (name, system prompt,
     allowed domains, target website URL).
   - Knowledge Base Hub: Document upload and website web crawler interface.
     Extracts text, segments chunks, and computes vector embeddings.
   - API Key Console: Generates prefixed keys (pk_live_... for widgets,
     sk_live_... for backend SDKs). Displays the secret key once upon creation;
     stores only SHA-256 hash.
   - Telemetry & Analytics: Tracks token usage, message counts, top visitor
     domains, and credit balances.

B. EMBEDDABLE CLIENT WIDGET (/widget.js, /embed.js)
   - Ultra-lightweight Vanilla JS script (<16KB).
   - Reads the client's public API key from the script attribute:
     document.currentScript.getAttribute('data-bot-key').
   - Mounts inside a closed Shadow DOM (attachShadow({ mode: 'closed' }))
     so host website CSS stylesheets cannot alter or break the chat UI.
   - Manages persistent chat sessions per visitor in browser LocalStorage.
   - Renders a floating launcher button, expandable modal, chat history,
     typing indicators, and quick action prompts.

C. SECURE API GATEWAY (/api/v1/widget/chat)
   - Serves as the central security and orchestration proxy for all chats.
   - Inspects HTTP "Origin" and "Referer" request headers.
   - Validates the incoming public key hash against allowed domains.
   - Enforces per-minute rate limits and atomic account credit balance deductions.
   - Orchestrates the RAG similarity search and feeds context to Google Gemini.

D. RAG & VECTOR ENGINE (src/lib/rag-engine.ts)
   - Chunking: Semantic boundary overlap chunker (750 chars max, 120 chars overlap).
   - Embedding: Generates 768-dimensional float vectors via Google Gemini.
   - Retrieval: Calculates vector dot-product cosine similarity against
     stored KnowledgeChunks for the target bot (minimum similarity threshold ~0.45).
   - Context Injection: Injects top-K chunks directly into the Gemini system prompt.

E. INGESTION & WEB CRAWLER (src/lib/crawler.ts)
   - Fetches arbitrary website URLs, strips HTML boilerplate, extracts main text,
     and pushes chunks to the RAG vector store automatically.


[5] DATABASE SCHEMA & ENTITY RELATIONSHIPS (Prisma)
--------------------------------------------------------------------------------

1. User (Table: users)
   - id: String (UUID, Primary Key)
   - email: String (Unique)
   - passwordHash: String
   - creditBalance: Int (Default 50 free credits, decremented per message)
   - Relations: bots (1-to-many), apiKeys (1-to-many)

2. Bot (Table: bots)
   - id: String (UUID, Primary Key)
   - userId: String (Foreign Key -> User)
   - name: String (e.g., "Mae Hong Son Travel Assistant")
   - systemPrompt: String (Bot persona, guidelines, language style)
   - model: String (Default: "gemini-3.5-flash-lite")
   - allowedDomains: String (Comma-separated whitelist or "*" for all)
   - websiteUrl: String? (Source URL for crawler)
   - isActive: Boolean (Default true)
   - Relations: apiKeys, usageLogs, knowledgeDocs, knowledgeChunks

3. KnowledgeDocument (Table: knowledge_documents)
   - id: String (UUID, Primary Key)
   - botId: String (Foreign Key -> Bot)
   - title: String (e.g., "mae_hong_son_guide.pdf")
   - fileType: String ("pdf", "docx", "txt", "faq", "markdown", "website")
   - chunkCount: Int
   - status: String ("indexing", "ready", "error")
   - Relations: chunks (1-to-many)

4. KnowledgeChunk (Table: knowledge_chunks)
   - id: String (UUID, Primary Key)
   - documentId: String (Foreign Key -> KnowledgeDocument)
   - botId: String (Foreign Key -> Bot)
   - content: String (Raw text snippet)
   - embedding: String? (768-dim float array serialized as JSON string)
   - chunkIndex: Int

5. ApiKey (Table: api_keys)
   - id: String (UUID, Primary Key)
   - botId: String (Foreign Key -> Bot)
   - userId: String (Foreign Key -> User)
   - keyPrefix: String (e.g., "pk_live_9b2f")
   - keyHash: String (SHA-256 hash string, Unique Index)
   - type: String ("PUBLIC_WIDGET" | "SECRET_SERVER")
   - rateLimitPerMinute: Int (Default 60)

6. UsageLog (Table: usage_logs)
   - id: String (UUID, Primary Key)
   - botId: String (Foreign Key -> Bot)
   - apiKeyId: String (Foreign Key -> ApiKey)
   - messageCount: Int (Default 1)
   - promptTokens: Int
   - completionTokens: Int
   - originDomain: String? (Extracted from client request header)
   - createdAt: DateTime


[6] CORE LIFECYCLES & STEP-BY-STEP WORKFLOWS
--------------------------------------------------------------------------------

WORKFLOW 1: KNOWLEDGE BASE INGESTION (RAG INDEXING)
1. Business user uploads a document or provides a website URL via Dashboard.
2. Ingestion handler receives text/file and calls chunkText(rawText, 750, 120).
3. The chunker splits paragraphs cleanly while keeping a 120-character overlapping
   window to maintain semantic continuity across chunk edges.
4. For each chunk:
   - generateEmbedding(chunkText) calls Gemini 768-dim embedding API.
   - The resulting vector is stringified to JSON and saved in `KnowledgeChunk`.
5. Document status updates to "ready".

WORKFLOW 2: WIDGET BOOTSTRAPPING ON CLIENT WEBSITES
1. External website developer includes:
   <script src="https://domain.com/widget.js" data-bot-key="pk_live_xyz..." defer></script>
2. widget.js executes immediately upon script load.
3. Finds its own script tag and extracts data-bot-key.
4. Injects a closed Shadow DOM container into document.body.
5. Injects floating chat bubble icon with badge counter.
6. When visitor clicks the bubble, opens responsive chat conversation window.
7. Retrieves existing sessionId from localStorage (or creates a random UUID).

WORKFLOW 3: CHAT REQUEST EXECUTION & SECURITY LIFECYCLE
1. User types question: "When is the best season to visit Mae Hong Son?"
2. Widget sends HTTP POST to: /api/v1/widget/chat
   Payload: {
     "publicKey": "pk_live_xyz...",
     "message": "When is the best season to visit Mae Hong Son?",
     "sessionId": "anon-session-1234"
   }
3. Chat Gateway (/api/v1/widget/chat) performs security checks:
   a. Computes SHA-256 hash of publicKey and queries `api_keys`.
   b. Verifies that the bot is active (bot.isActive === true).
   c. Header Check: Extracts "Origin" or "Referer". Compares against bot.allowedDomains.
      - If domain is not authorized -> returns HTTP 403 Forbidden.
   d. Rate Limit Check: Verifies request frequency per minute.
      - If limit exceeded -> returns HTTP 429 Too Many Requests.
   e. Credit Check: Verifies owner user.creditBalance > 0.
      - If 0 credits -> returns HTTP 402 Payment Required.
4. RAG Retrieval Step:
   a. Gateway generates query vector for visitor question via generateEmbedding().
   b. Queries all KnowledgeChunks belonging to botId.
   c. Computes cosine similarity between query vector and stored chunk embeddings.
   d. Filters chunks with similarity >= 0.45 and selects top 3 to 5 chunks.
5. Prompt Assembly & Inference:
   a. Merges Bot System Prompt + Retrieved Knowledge Context + User Question:
      System Prompt: "You are Mae Hong Son travel assistant..."
      Context: "[Source: Guidebook] November to February is cool season..."
      User: "When is the best season to visit?"
   b. Dispatches request to Google Gemini API (gemini-3.5-flash-lite).
6. Accounting & Persistence:
   a. Atomically decrements 1 credit from user.creditBalance.
   b. Creates a new record in `usage_logs` capturing token metrics and origin domain.
7. Gateway returns JSON response:
   { "reply": "The best time to visit Mae Hong Son is November to February..." }
8. Widget renders message in conversation view and caches it in localStorage.


[7] SECURITY ARCHITECTURE & DESIGN HIGHLIGHTS
--------------------------------------------------------------------------------
1. Zero Plaintext API Keys:
   Plaintext keys are displayed strictly once upon generation. Only the SHA-256
   hash is persisted in the database. When a request arrives, the key is hashed
   on the fly and matched via indexed lookup.
2. Browser-Enforced Origin Whitelisting:
   Even if an attacker steals a public key (pk_live_...), they cannot use it on
   an unauthorized website because modern browsers enforce immutable "Origin"
   and "Referer" headers that cannot be spoofed by client scripts.
3. Shadow DOM Style Isolation:
   Zero CSS leakage in both directions: host website styles cannot break the
   chat interface, and the chat widget's Tailwind styles cannot alter the host site.
4. Offline / Resilience Fallback:
   If the Gemini embedding API undergoes rate limits or network issues, the
   engine automatically falls back to a deterministic 768-dimensional sinusoidal
   hashing function to prevent downtime.
